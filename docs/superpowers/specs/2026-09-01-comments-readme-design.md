# 设计：全量更新代码注释与 README

日期：2026-09-01  
仓库：`github.com/notes-bin/ddns6`  
状态：待用户审阅 spec 后实施

## 背景与目标

用户选择方案 **2（全面重写）**：对全部 `.go` 文件（含测试与未导出符号）按仓库约定统一重写中文注释，并整体重写 `README.md`，使其与当前 23 家运营商、CI、Docker、架构行为一致。

成功标准：

1. 每个包有且仅有一处合格的 `// Package ...` 注释（写在同包某一非测试文件）。
2. 生产代码中每个导出类型/函数/方法/重要常量具备中文 godoc；未导出符号具备意图级中文注释。
3. 测试文件中每个 `Test*`（及关键辅助类型/函数）有一句用途说明；表驱动依赖 `name`，不堆砌行内注释。
4. `README.md` 按下方大纲重写，事实与代码一致（含 `test.yml`）。
5. 不改变运行时行为；`gofmt` 通过；`go test ./...` 通过。

## 方案选择

采用 **分层批次 + 统一注释规范**（设计讨论中的方案 B）：

- 相对「无规范一次性全文重写」更可审阅、风格更稳。
- 相对「脚本模板补缺」注释质量更高，避免低信息复述。

## 注释规范

### 语言与风格

| 项 | 约定 |
|----|------|
| 注释语言 | 简体中文 |
| 标识符 | 英文（变量/函数/类型名不翻译） |
| 术语 | 技术术语可保留英文，首次可附中文；API/HTTP/JSON 等无需翻译 |
| 错误日志 / API 响应文案 | 保持英文，本次不改 |

### 包注释

- 每个包只在一个非 `*_test.go` 文件声明 `// Package <name> ...`。
- 同包其他文件**不**重复包注释。
- 包注释说明职责、主要入口、与相邻包的边界。

### 符号注释

- **导出**：godoc 首句以符号名开头；说明用途、重要参数/返回值语义、调用约束。
- **未导出**：说明 why / 边界 / 不变量；禁止「设置 xxx」「返回 yyy」类纯复述。
- **结构体字段**：导出或易混淆字段保留行尾或块注释；显而易见字段可不强行注释。
- **行内注释**：只保留解释意图、坑、协议细节的内容；删除装饰性分隔线过多或与代码同义的句子（保留包/文件级必要分区若有助于导航则可精简保留）。

### 测试注释

- 每个 `TestXxx` 上方一句中文说明测什么。
- 辅助 mock/fetcher 类型与方法补一行用途。
- 表驱动子用例以 `name` 表达场景，不为每个断言加注释。

### 明确不做

- 不重构逻辑、不改函数签名、不改对外行为。
- 不为每个 `if`/`case` 强行加注释。
- 不把 `.env.example` / `docker-compose.yml` 纳入本次必改范围（README 引用须正确即可）。
- 不新增面向用户的长篇 `docs/` 手册（本文件为流程所需设计 spec）。

## README 重写大纲

1. 简介 + badges（Go 1.25+、License；可提及 CI Test workflow）
2. 快速开始（安装 / 临时 run / init / check）
3. 命令参考（全局参数与 `run`/`check`/`list`/`clean`/`init`/`version`/`completion`）
4. 支持的 DNS 运营商（23 家表 + acme.sh 对照 + 阿里云 V3）
5. 配置文件格式
6. Docker 部署（安全要点与两种模式）
7. systemd 部署
8. 安全注意事项
9. 架构说明（触发器、防抖、同步流程、IPv6 源）
10. 项目结构（含 `.github/workflows/test.yml` 与 `release.yml`）
11. 开发（`make test`、vet、race/cover、加运营商步骤）
12. 常见问题 + License

内容以仓库现状为准；结构可沿用现 README，但视为整体重写（可删改过时段落、补齐缺口）。

## 实施批次

每批完成后：`gofmt` 相关文件 + 对该范围 `go test`（整仓收尾跑 `go test ./...`）。

| 批次 | 范围 |
|------|------|
| 1 | `main.go`、`cmd/` |
| 2 | `internal/ddns/`、`internal/config/`、`internal/crypto/` |
| 3 | `pkg/domainutil/`、`pkg/ipaddr/`、`pkg/retry/` |
| 4 | `internal/providers/*`（可按多批发完 23 家） |
| 5 | 全部 `*_test.go`（可与对应包批次合并，但须覆盖） |
| 6 | `README.md` |

工作区若仍有未提交的测试简化改动，可与注释批次一并整理，或先单独提交 simplify 再改注释；实施时以「注释/文档提交」与「行为改动提交」分离为佳。

## 验收清单

- [ ] 包注释唯一且完整
- [ ] 生产代码导出符号均有中文 godoc
- [ ] 未导出关键符号有意图注释；低信息注释已清理
- [ ] 测试函数具备用途说明
- [ ] README 与 23 providers / CI / Docker / 架构一致
- [ ] `gofmt` + `go test ./...` 通过
- [ ] 无故意行为变更（diff 以注释与 README 为主）

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| 注释噪声过大、难审 | 按批次提交；遵循「意图优先」规范 |
| 误改逻辑 | 禁止顺手重构；每批跑测试 |
| 与未提交 simplify 混杂 | 提交时按主题拆分 |
